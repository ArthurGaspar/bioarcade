# CLAUDE.md

BioArcade: four genomics teaching games and a CRISPR guide workbench. A Python pipeline turns Ensembl data into static
JSON; a React + TypeScript (Vite) site renders it on GitHub Pages. No backend, no API keys.

Detailed docs live in [`docs/`](docs/README.md). Read the relevant page before changing a subsystem.

## Layout

```
pipeline/        Python. analyze.py (slow, networked) and build.py (fast, offline)
data/genes/      Committed per-gene analyses; the source of truth for the site
data/variants.json  Hand-curated ClinVar snapshot for Variant Verdict
tests/           pytest for the pipeline and game-round builders
web/src/         React app. lib/ = pure logic, games/ = game screens + reducers
web/public/data/ Generated by `python -m pipeline.build` (gitignored)
docs/            Stable documentation and README screenshots
```

## Commands

Run from the repo root unless noted. On Windows the venv lives at `.venv/Scripts/`.

```bash
pip install -r requirements.txt
python -m pipeline.build            # regenerate web/public/data (needed before npm dev/test)
python -m pytest                    # pipeline tests
python -m pipeline.analyze          # networked; only genes missing from data/genes
python -m pipeline.analyze --only TP53 --refresh

cd web
npm install
npm test                            # vitest, includes Python/TS parity tests against data/genes
npm run build                       # tsc --noEmit && vite build
npm run dev
```

CI (`.github/workflows/pages.yml`) runs: pytest → `pipeline.build` → `npm ci && npm test && npm run build`, then
deploys `web/dist` on pushes to `master`. CI never runs `pipeline.analyze`.

## Rules that are easy to break

- **Python and TypeScript must stay in lockstep.** `web/src/lib/crispr.ts` mirrors `pipeline/guides.py` (guide search,
  scoring, *and the exact wording of every reason string*), `pam_sites` in `pipeline/analyze.py`, and
  `codingSlice` in `web/src/lib/ensembl.ts` mirrors `_coding_slice` in `pipeline/transcripts.py`.
  `web/src/lib/codons.ts` must translate identically to `pipeline/transcripts.translate`. Change both sides together;
  `crispr.test.ts` and `codons.test.ts` re-check every published guide and excerpt.
- **Scoring rules have three places**: the `score()` logic, the `RULES` table in `pipeline/guides.py` (published in
  `meta.json` and shown on the site), and `scoreSpacer` in TS. Changing a rule means re-running `pipeline.analyze
  --refresh` so committed `data/genes/*.json` match, otherwise the parity test fails.
- **Coordinates**: exon sequences are on the transcript's strand (5'→3'); `cds_start/cds_end` are exon-local and
  half-open; `cds_offset`/`cut` are 0-based CDS positions. Minus-strand genes are the usual source of bugs. See
  [docs/pipeline.md](docs/pipeline.md#coordinate-conventions).
- **JSON shape is a contract** between `pipeline/build.py` and `web/src/data.ts`. Update the TS interfaces when changing
  output. Guide fields use `in_cds` (snake_case, from the Python dataclass); everything else is camelCase.
- **Don't hand-edit `data/genes/*.json`**; regenerate with `pipeline.analyze`. `data/variants.json` *is* hand-edited:
  update clues, metadata and `reviewedAt` together. Unknown `classification` labels intentionally raise in
  `pipeline/variants.py`.
- `pipeline.build` must stay offline and deterministic.
- Off-target specificity is meaningless for guides with `in_cds: false`; games must only use fully coding guides.

## Conventions

- Python: standard library + `requests` + `numpy`, no frameworks. Module docstrings explain *why*; keep them.
- TS: strict mode, `noUnusedLocals`. No router, state library or CSS framework: hash routing lives in `App.tsx`,
  game state in reducers (`games/runner.ts`, `games/verdict.ts`) or local `useState`, styles in `theme.css` (tokens,
  light/dark via `[data-theme]`) and `styles.css`.
- Data loads go through `load<T>(name)` in `web/src/data.ts` (cached, retried on failure) and `useAsync` in `ui.tsx`.
- Game logic that awards points belongs in a pure reducer with tests, not inline in a component.
- User-facing copy is plain English, precise about scientific limits; never imply clinical or lab-grade use.
- Commit messages: `type(scope): summary` (e.g. `feat(web): ...`, `feat(core): ...`), often written in Portuguese.
- `web/index.html` loads a cross-promo `ads.js` from the author's profile site; leave it alone unless asked.
